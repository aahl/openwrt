> 适用机型：京东云 RE-CS-02 / 京东云亚瑟 AX1800 Pro（RE-SS-01）/ Link NN6000 v2
> 本文所有参数与结论均经三台实机 SSH 验证（2026-11-21），对应固件版本 v2.1.2 内核构建。

## 2. dae 代理

### 2.1 配置文件与 LuCI 的关系（重要）

- 真正生效的配置是 **`/etc/dae/config.dae`**（dae 自有 DSL 语法，**不是 JSON**）。
- LuCI「服务 → Dae」：
  - 「全局设置」页改的是 UCI（`/etc/config/dae`：enabled / config_file / 日志参数），**不是** `global {}` 段；
  - 「DNS / 节点 / 路由设置」编辑的是 **`/etc/dae/config.d/{dns,node,route}.dae`**，保存后自动触发 `hot_reload`；
  - 因此必须先在 `config.dae` 顶部写 `include { config.d/*.dae }` 并把对应段落拆出去，界面改动才会生效，**每个段只能存在于一个文件里**。
- **权限坑（源码级确认）**：dae 对主配置和每个被 include 的文件都检查权限，`0644` 会被拒绝，要求 **0640/0600**。LuCI 首次新建文件是 0644 → 热重载被静默拒绝；但重写已有文件保留权限。所以：**SSH 建一次骨架 + `chmod 640`，之后界面编辑永久生效**。
- reload 失败会**静默保持旧配置**，改完务必 `logread -e dae | tail` 确认。

### 2.2 参考配置（最终版，v2.1.2 逐项核对）

```dae
global {
    log_level: info
    lan_interface: br-lan
    wan_interface: auto
    auto_config_kernel_parameter: true
    allow_insecure: true          # 节点全为正规证书就改 false

    tcp_check_url: 'http://cp.cloudflare.com,1.1.1.1'   # 全网屏蔽 v6,去掉 v6 成员
    udp_check_dns: '8.8.8.8'
    check_interval: 300s
    check_tolerance: 50ms

    dial_mode: domain++
    sniffing_timeout: 100ms       # ★ v2 起默认降为 30ms,domain++ 依赖嗅探,必须显式钉住
    fallback_resolver: '223.5.5.5:53'
}

dns {
    ipversion_prefer: 4           # 只回 A 记录,客户端不再撞 v6
    upstream {
        alidns: 'udp://223.5.5.5:53'
        googledns: 'tcp+udp://8.8.8.8:53'   # IP 型:按 routing 走代理出去,抗污染
    }
    routing {
        request {
            qname(geosite: cn, geosite: china-list) -> alidns
            qname(geosite: google@cn) -> alidns
            # qname(geosite: category-ads-all) -> block   # 可选去广告
            fallback: googledns
        }
        response {
            upstream(googledns) -> accept
            ip(geoip: private) -> accept      # 内网域名别转 googledns 打转
            !ip(geoip: cn) -> googledns       # alidns 答案非国内 IP → 疑似污染重查
            fallback: accept
        }
    }
}

subscription {
    my_sub: 'https-file://xxxx'   # 自动缓存到 /etc/dae/persist.d/,订阅挂了用上次结果
}

group {
    proxy {
        filter: !name(regex: '过期|到期|剩余|流量|套餐|官网|Expire')
        policy: min_moving_avg
    }
}

routing {
    pname(dnsmasq, dropbear) -> must_direct
    dip(127.0.0.0/8) -> must_direct
    dip(224.0.0.0/4, 'ff00::/8') -> direct    # 组播必须排在 ipversion(6) 之前!
    dip(geoip: private) -> direct

    # 可选:PT 下载机整机直连(盖住 peer 裸 IP 流量),二选一
    # sip(192.168.68.50) -> direct
    # mac('AA:BB:CC:DD:EE:FF') -> direct

    domain(geosite: category-pt) -> direct            # PT 站,必须在下面 gfw 行之前
    domain(geosite: category-public-tracker) -> direct # 公共 BT tracker
    # domain(geosite: category-pt@!cn) -> proxy        # 可选:境外 PT 直连慢就启用(放上一行之前)

    ipversion(6) -> block                      # 家宽有可用 v6 就删这行
    domain(geosite: cn, geosite: china-list) -> direct
    dip(geoip: cn) -> direct
    l4proto(udp) && dport(443) && domain(geosite: youtube, geosite: google) -> block
    domain(geosite: gfw, geosite: geolocation-!cn) -> proxy
    dip(geoip: telegram) -> proxy               # 依赖 Loyalsoldier geoip 的 telegram 段

    fallback: proxy
}
```

要点：路由顺序 bug 修正（组播/国内 v6 误杀）、geolocation-!cn 已含所有大厂分项不逐条列、
`category-pt` / `china-list` 依赖固件内置的 **Loyalsoldier 增强版 dat**（类别名在 dat 内大写存储，dae 匹配不区分大小写；换 v2fly 官方 dat 需删这些行）。

### 2.3 geosite / geoip 自动更新

dae 官方明确**不做内置更新**（[dae#1019](https://github.com/daeuniverse/dae/issues/1019)）。本固件已内置完整方案：

- **原理**：dae 按 `/etc/dae` → `/usr/share/dae` 的顺序搜索 dat（源码 `common/assets/assets.go`）。固件把 Loyalsoldier dat 烧在只读分区 `/usr/share/dae/`；更新脚本把最新 dat 落到可写的 `/etc/dae/`，自动压过内置版本，旧文件保留为兜底，且跨 sysupgrade 持久。
- **机制**：`/etc/dae/update-geodata.sh`（源文件在仓库 `Scripts/update-geodata.sh`），每天 04:30 由 crond 触发：
  - dae 未启用直接退出；dat 每 7 天最多下载一次（戳记 `.geodata_stamp`），其余执行只做热重载（顺带每日刷新订阅）；
  - 多镜像下载 + 大小 + sha256 双校验，失败保留旧文件，次日重试；
  - 下载成功后 `/etc/init.d/dae hot_reload` 热重载（SIGUSR1，不断连接）。
- **计划任务自愈**：cron 行烧两份——ROM 的 `/etc/crontabs/root` + uci-defaults `99_dae_geodata` 幂等补写（按脚本路径探测，手动改过执行时间也不会重复添加）。原因：sysupgrade 保配置时 OpenWrt 默认保留 `/etc/crontabs/`，旧文件恢复会盖掉 ROM 新版，表现为**升级后 LuCI 计划任务里看不到 geodata 任务**（实机踩坑，`cat /rom/etc/crontabs/root` 有而 `/etc/crontabs/root` 没有）。自愈之前的固件升级上来，手动补一行即可：
  `echo '30 4 * * * /etc/dae/update-geodata.sh >/dev/null 2>&1' >> /etc/crontabs/root && /etc/init.d/cron restart`
- **手动**：`/etc/dae/update-geodata.sh && logread -e dae-geodata`
- **可调**：脚本头部 `FRESH_DAYS` / `MIRRORS`；执行频率在 `WRT-CORE.yml` 的 crontab 行与 `Scripts/99_dae_geodata`（两处需一致）。
- 验证 dae 读的是哪个 dat：临时把 `log_level` 改 `debug`，`logread -e dae | grep Found`。

### 2.4 PT/BT 直连

- 站点+tracker：`domain(geosite: category-pt) -> direct`（v2fly 社区维护的 PT 大合集：M-Team/HDSky/CHD/OurBits/学校站/境外 PT 等），**必须放在 `gfw/geolocation-!cn -> proxy` 之前**。
- peer 流量是裸 IP，域名规则管不到：国内 peer 已被 `dip(geoip:cn)` 盖住；**境外 peer 会掉进 `fallback: proxy`**。要彻底直连给下载机加一条 `sip(<固定IP>) -> direct` 或 `mac('<MAC>') -> direct`（v2.1.2 均支持）。

### 2.5 给程序提供 HTTP 代理口（如 `PROXY_HOST=http://IP:端口`）

**dae 没有 HTTP/SOCKS 入站监听**（纯 eBPF 透明代理；`tproxy_port: 12345` 是内核内部通道，别连）。两个办法：

1. 设备改得动网关/DNS → 旁路由模式（见 2.6），零组件；
2. 程序只认代理变量 → 在跑 dae 的机器上装 **tinyproxy**（feed 里有 `net/tinyproxy`），它的出站会被 dae 自动接管分流，这个端口"天然就是代理"。注意 HTTP 代理只走 TCP；DNS 污染靠 `dial_mode: domain++` 嗅探兜底自愈。

### 2.6 旁路由模式

- **哑节点 ≠ 旁路由**：客户端网关仍指向主路由时，流量二层桥接穿过 AP（目的 MAC 是主路由的），**dae 挂在 br-lan 上的 TC 根本看不见**，只有把网关+DNS 指到本机的设备流量才会被三层接管。
- 客户端把**网关和 DNS 一起**指向旁路由（如 192.168.68.2）；只改网关不改 DNS 的话域名分流只剩嗅探兜底、污染防护全失效。
- 旁路由下 `wan_interface: auto` 会绑到 br-lan（日志显示与 LAN 同口），这是官方旁路由形态，正常。
- `auto_config_kernel_parameter: true` 会自动关 `send_redirects`（含 `conf/all`，v2.1.2 修复 #1125）——这正是旁路由的关键内核参数，无需手动 sysctl。
- 主路由别再叠一层代理。性能预期：代理流量走 CPU（IPQ60xx 四核 A53，几百兆），直连回程 NSS 硬加速。
- 验证：客户端改完指向后 `logread -e dae | grep "<客户端IP>"`，能看到带 `mac=` 的分流日志才算真接管。

### 2.7 升级 dae 核心（维护者）

- 版本 pin 在 `.github/workflows/WRT-CORE.yml` 的 `Update Dae Core/Config` 步骤（预编译二进制覆盖 `/usr/bin/dae`；init/UCI 来自 immortalwrt feed 的 dae 包）。
- 升前核对：init 用到的 CLI 参数（`--config/--logfile/--logfile-maxbackups/--logfile-maxsize/--disable-timestamp`）、`/var/run/dae.pid` + `reload [pid]`、geodata 搜索顺序、`sip()/mac()` 等路由函数。
- **v2 起官方 zip 内附带官方版 dat 和 example.dae**，`unzip -j dae.zip dae-linux-arm64` 只提取二进制，**切勿全量解压**覆盖内置 Loyalsoldier dat。
- v2 以后 `sniffing_timeout` 默认 30ms，`domain++` 场景显式写 `100ms`。

## 3. Mesh 漫游（usteer）

### 3.1 决策模型：协商优先，踢线只做兜底（与主流同构）

主流厂商（Google Nest / TP-Link Deco / UniFi / Aruba / Ruckus）的引导是同一副骨架，没有谁按"几何距离"切：

1. 终端自愈漫游打底（手机本来就会自己切）；
2. **802.11k**：AP 让终端亲自测量各邻居 AP 并上报 Beacon Report（终端视角"谁链路最好"）；
3. **802.11v BTM 请求-响应协商**：终端可以接受，也可以拒绝并给理由码；
4. 拒绝就退避不再骚扰，仍不走则 BTM 加"即将断开"位、再上倒计时逐级加压；
5. 实在不走的终端才断开，且断开后旧 AP 拒绝其立即重连（防"踢-连"弹跳，逼终端全扫描落到实际最优 AP——Ruckus SmartRoam 同思路）。

usteer 自 2024-10（commit `49ba5f1`，openwrt/packages master 已 pin `2026-05-19/7532e12`）实现了同一套阶梯（`aggressiveness` 0-4，per-MAC 可覆盖），三节点每 1s（`remote_update_interval`）UDP 广播同步节点状态/终端信号/11k 测量报告，选优在**全节点视图**上进行。集群算力从来不是瓶颈（决策 O(客户端×节点)），瓶颈是策略——旧固件用 `roam_scan_timeout=0` + 高 `min_snr` 把协商阶梯完全旁路，只剩"不管"和"大锤"两档。

关于"按距离切"：真·测距是 802.11mc FTM（米级），本机 ath11k 驱动无 FTM responder、终端侧支持也寥寥，此路不通；RSSI 指纹定位项目（Find3 / room-assistant 一类）为房间级存在检测设计，学习成本高、时延大，不适合秒级漫游决策。业界统一用 **RF 链路质量当距离代理**（隔承重墙 3 米不如同屋 8 米）——usteer 的 11k 双视角测量（终端上报的 beacon report + 各 AP 听到的上行信号）覆盖的就是这件事。

### 3.2 默认参数（协商阶梯版，`99_meshtopo` 写入）

固件 uci-defaults 按版本探测写入。**阈值一律用负数 = 绝对 dBm**（usteer 语义：SNR 值为负时直接当 dBm，不随各节点噪声底换算）——实测教训：usteer 的 SNR→dBm 换算用的是 survey 噪声底，5G 上 ath11k 报 ≈**-95** 而非早期假设的 -104，SNR 值 30/24/14 的真实阈值其实是 -65/-71/-81dBm，比文档以为的严苛得多，正是"死角里信号可用却被拒"的元凶。

| 参数 | 值 | 语义 | 说明 |
|---|---|---|---|
| `roam_scan_snr` | -74 | 低于 -74dBm 起温和引导（11k 扫描 + 11v 协商） | 绝对 dBm，不随噪声底漂移 |
| `signal_diff_threshold` | 10 | 目标 AP 至少好 10dB 才引导，防乒乓 | 不变 |
| `aggressiveness` | 3 | 协商阶梯：BTM 请求 → 终端拒绝即**取消踢线**并退避 → 仍不走加倒计时 → 到期才断 | 1=纯协商 / 2=+断开警告 / 3=+倒计时（推荐） / 4=+强制 deauth |
| `roam_scan_timeout` | 20000 | 3 次引导无响应 → 冷却 20s 再试 | 踢线交给协商阶梯，不再"3 次就踢" |
| `min_snr` | -90 | 兜底大锤：低于 -90dBm 才踢/拒 | 绝对 dBm；且固件补丁要求"存在更优候选"才动手 |
| `min_snr_kick_delay` | 10000 | 连续 10s 低于兜底才踢 | 过滤人体/拐角瞬时遮挡 |
| `steer_reject_timeout` | 60000 | 终端明确拒绝协商后 60s 内不再骚扰 | "协商"的尊重面 |
| `roam_kick_delay` | （默认 10000） | BTM 倒计时长度，到点终端仍不走才断 | aggressiveness ≥ 2 生效 |

调参思路一句话：**温和引导管"该切了"，协商阶梯管"劝得动"，min_snr 大锤只管"真不能用了"，补丁保证大锤只砸"有地方可去却不挪"的终端**。嫌踢得勤/懒只动 `min_snr`（-90±3，勿高于 -85——超了会重新挤占协商走廊）。

per-MAC 覆盖（顽固 Windows / 老 IoT，按需手工加，格式 `<小写MAC>,<0-4>`）：

```sh
uci add_list usteer.@usteer[0].aggressiveness_mac_list='aa:bb:cc:dd:ee:ff,4'  # 顽固 Windows：到期强制断
uci add_list usteer.@usteer[0].aggressiveness_mac_list='11:22:33:44:55:66,1'  # 老 IoT：只协商永不强踢
uci commit usteer && /etc/init.d/usteer reload
```

旧版 usteer（二进制探测不到 `aggressiveness_mac_list`）自动回退实机调优值：`min_snr=24`、`roam_scan_timeout=0`（3 次引导无响应升级踢线；>0 = 永远只重试不踢，粘性终端切不走，实测踩坑）。升级固件但保留配置时 uci-defaults 不会重跑，想套用新默认可对照上表手工改 `/etc/config/usteer`。

### 3.3 "拒绝进虚空"：厕所示例与三层修复（源码实锤）

实测案例：厕所往往是全屋覆盖死角，亚瑟已是手机能摸到的最强 AP（-75 ~ -85dBm，可用），但 usteer 仍拒绝关联——手机哪都连不上。拆开是三层问题：

1. **阈值换算踩坑**：usteer 把 SNR 阈值换算 dBm 用的是 survey 噪声底（5G ath11k ≈-95），旧 `min_snr=24` 实际阈值是 **-71dBm**（不是文档以为的 -80），协商版 14 也是 -81——厕所信号正好落网。→ 已改**负数绝对 dBm**（-90），不再随噪声底漂移。
2. **上游拒收不看候选**：`usteer_check_request`（policy.c）在 `min_snr` 之下**无条件拒绝 assoc**（防"踢-连"死循环的官方对策，`f923394` 弱信号死循环的修复面）——但客户端没有更好的去处时，弱连接好过没连接。→ 固件补丁 `patches/001-usteer-candidate-aware-assoc-kick.patch`：拒绝前先 `find_better_candidate` 查全节点视角，没有更优候选就放行。
3. **踢线同理**：`min_snr` 大锤原本也不看候选，把"无处可去"的终端踢了只会弹回同一个 AP。→ 同一补丁：踢之前同样查候选，没有更优候选就不踢。

补丁由 Settings.sh 注入 `feeds/packages/net/usteer/patches/`（与 vlmcsd 补丁同机制），基于 feed pin 的 7532e12 源码制作并经 `git apply --check` 验证；日后升级 usteer 若 hunk 失配会构建失败提醒，届时移植或移除。

### 3.4 漫游域一致性铁律（本次实锤的根因）

同一 SSID/同 mobility_domain 的所有 AP 必须完全一致，否则客户端认证混乱、抱死旧 AP：

- 相同 `encryption`（**别一台 sae-mixed、一台 psk2**，MFP 状态也要一致）；
- 相同 `mobility_domain` + **`ft_psk_generate_local='1'`**——缺这个（默认 0）FT 密钥生成直接断裂；
- 固件的 99_meshtopo 已加 guard：任何开了 11r 却缺 `ft_psk_generate_local` 的 iface 自动补 1（LuCI 手建 AP / 升级恢复配置都会被保护）。

### 3.5 排障工具箱（SSH）

```sh
# 版本/协商能力确认(无 aggressiveness = 旧版 usteer,固件已自动回退保守参数)
ubus call usteer get_config | grep -E 'aggressiveness|min_snr|roam_scan'
# 每客户端漫游状态机(state/tries/信号/能力)
ubus call usteer connected_clients
ubus call usteer get_clients
ubus call usteer get_client_info '{"address":"<MAC>"}'
# 三节点互通与各自视角
ubus call usteer remote_info
# 各节点实际噪声底(SNR 阈值换算依据;绝对 dBm 阈值下仅供观测)
ubus call usteer local_info | grep -E '"noise"|"ssid"'
# hostapd 实际运行配置(uci 有 ≠ 生效!)
grep -E 'wpa_key_mgmt|ft_psk|mobility|bss_transition|rrm' /var/run/hostapd-phy*.conf
# 提高日志级别看决策
uci set usteer.@usteer[0].debug_level='4' && uci commit usteer && /etc/init.d/usteer restart
logread -e usteer | grep -v 'Received message'
```

排障顺序建议：先 `get_config` 确认协商参数在位（无 `aggressiveness` = 旧版，固件已自动回退保守参数）→ `connected_clients` 看该终端 `bss-transition-response.status-code`（是否拒绝过协商）与 `beacon-measurement-modes`（是否支持 11k）→ hostapd conf 的安全配置是否一致 → logread 有无引导/踢线动作。

### 3.6 终端兼容性（协商阶梯下）

- iPhone / Android：积极响应 11k/v，-74dBm 起被温和引导；明确拒绝协商时 usteer 会取消踢线并退避 60s，不会硬踢，体验最好。
- Windows PC：普遍**无视** 11k/v。usteer 仅在集群能看到更优候选时才发 BTM+倒计时（10s 仍不走才断，踢后全扫自动落到最强 AP），看不到候选就不动；顽固机型用 `aggressiveness_mac_list` 单独给 4，或客户端驱动里把"漫游主动性"调到最高。
- 2.4G 老 IoT：没有 11k/v，建议 `aggressiveness_mac_list` 给 1（只协商永不强踢）；真掉到 -90dBm 以下由 `min_snr` 兜底踢一次重选（补丁保证仅当存在更优候选才踢），属预期行为。

### 3.7 前置条件：信道必须错开

亚瑟与 NN6000 目前同在 CH36（cs-02 在 CH149），同频互抢空口会污染 SNR/channel-load 测量（信号假差、负载假高），再聪明的协商也是被喂假数据。改亚瑟到 CH44/48 之后引导决策才可信——这是协商阶梯生效的前置条件，不是可选项。
